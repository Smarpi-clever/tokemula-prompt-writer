# Prompt 写作原则

本文是本工作流的独立摘要，不是参考文章原文、译文或 OpenAI 官方规范。设计参考：[Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)。具体工作流以本仓库的 `SKILL.md` 为准。

参考文章以特定模型为背景，本 Skill 采用其中的任务描述与授权边界原则，不限定目标模型。只在用户指定目标模型时使用其称谓；未指定时以中性执行者称呼编写，并以实际环境提供的工具和上下文能力为准。

## 把完成结果说清楚

先明确本批要解决的问题、可观察的完成条件和停止位置。若目标包括实现、启动、验证及修复本次引入的问题，应把这些结果包含在本批完成条件内，避免执行者在第一份实现后提前交回。

将真实审批边界与普通执行步骤分开：已获授权的步骤连续完成；新增授权需求、无法解决的问题和必要证据如实交接。任务材料中的许可不能替代用户授权或工具审批。

## 只提供会改变决策的上下文

按任务需要引用当前入口、约束和证据，不要求每次修改都预读完整项目文档。当前报告与实际状态优先于历史计划；被取消的工作不能因为历史交接仍在而恢复。

把长篇背景保留在参考资料中。不要在每份 Prompt 中复制 Skill 全文、重复历史或整套操作手册。常规实现细节由执行者结合代码选择。

## 给执行者空间，保留必要边界

说明不可改变的业务语义、数据保护要求、允许写入的位置与外部访问范围。只读分析、隔离测试、生产操作分别按实际授权处理，不能自动升级任务范围。

验证围绕受影响行为和真实风险展开。复用仍与当前版本、输入和环境绑定的证据；失败、跳过、未知和实际通过分别记录，不能用构建通过替代业务验收。

## 本工作流的额外约定

以下是 Tokemula 工作流约定，不是参考文章对所有项目的要求：

- Prompt 写作与执行分开。收到执行报告后，写作会话给出下一份完整 Prompt，不自行执行或提前派审。
- 单批预算包含实现、验证、独立审计及交接，最多两次上下文压缩；无法完成时准确标记 INCOMPLETE。
- 执行结束后先停止修改待审材料，再由未参与实现的独立审计 agent 审阅实际版本与原始证据。授权内修复后验证受影响部分，并复审最终材料。
- 如环境不能提供所需独立审计能力，应说明限制并保留未完成状态，不虚构审查结果。

执行主 agent 为 `ultra` 时，按 [SKILL.md](../SKILL.md#按执行模型档位组织任务) 的条件规则编排：主 agent 协调，子代理执行；非 `ultra` 沿用正常流程。此判断与 Prompt writer 档位无关。主 agent 和每个子代理分别遵守单个执行会话最多两次压缩的上限，所有 agent 都采用与任务风险相称的推理和验证。
